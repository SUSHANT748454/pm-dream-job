Connect Supabase — accounts (magic link) + cross-device sync + jobs mirror

Adds a real backend without giving up the static architecture: every
Supabase call is client-side, so all routes stay static, and the whole
integration is null-safe — with no NEXT_PUBLIC_SUPABASE_* env vars the
app runs exactly as before (localStorage only, sign-in UI hidden).

Auth
- @supabase/supabase-js browser singleton (src/lib/supabase/client.ts)
- AuthProvider + useAuth() (email magic link, PKCE, localStorage session)
- /auth/callback — static page, client waits for the session then routes
- AccountMenu in the header; SignInDialog; SyncNudge on the dashboard

Sync layer
- src/lib/synced-store.ts — "localStorage first, Supabase when signed in"
- useProfile / useResume / useTracker refactored onto it, same return
  shapes (+ a `syncing` flag). Writes hit localStorage synchronously and
  fire-and-forget an upsert when signed in; first sign-in migrates local
  data up; the tracker merges per-job by updatedAt.

Schema (supabase/schema.sql)
- companies, jobs        — public read, service-role writes
- profiles, resumes, applications — RLS: auth.uid() = user_id

Jobs pipeline
- scripts/ingest/supabase-sink.ts upserts jobs + companies (service role,
  skipped when env unset) and prunes removed rows. The site still reads
  the committed jobs.json snapshot (static, SEO-preserving).
- refresh-jobs.yml: pass SUPABASE_* secrets; drop [skip ci] from the
  refresh commit so Vercel actually redeploys when jobs change.

Also: new analytics events sign_in_link_sent / signed_in / signed_out;
.env.example; docs/06-supabase.md + supabase/README.md; "stays on your
device" copy now notes optional sync.
